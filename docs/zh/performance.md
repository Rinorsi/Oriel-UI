# 粒子与动画性能：开工前必读

## D36 统一比较入口

引擎 old/new 使用[统一 CPU 基准工具](d36-mcp-bench.md)：`node tools/bench/run.mjs --config <工作区配置> --manifest <冻结清单> --out <新输出目录>`。先--freeze记录21页与资源摘要，提前经gws构建，工具自动进入bench-window。默认逐轮配对差值+A/A噪声底+95% Student-t置信区间检查每页p50/p95，区间未能证明不退化或噪声过大均不通过；进程前后探测并记录外部java/Minecraft提示，不沿用旧25%容差。

--synthetic 生成27种压力页，hover迁移仍需输入适配器；tools/bench/effects.mjs 比较已捕获15效果120帧，不执行捕获、不批准基线。独立样式/布局成本与实机 GPU/IME 不在默认 FrameBenchmark 输出中。配置、退出码与限制见上述手册。

[制作流程](ui-workflow.md) · [脚本合同](scripting.md) · [验收](validation.md)

这份规范适用于页面作者和 agent。保护上限不等于流畅预算：脚本没超时、strict 没报错，都不能证明游戏里不卡。先保留数量、种子、轨迹、进退场和交互，再优化执行方式；不能靠删特效或缩短播放伪装性能提升。

## 开工前确定绘制路线

| 内容 | 使用方式 | 原因与限制 |
|---|---|---|
| 文字、按钮、布局、原生物品与角色 | 原生页面元素；缓存引用 | 保留字体、命中、布局和 Minecraft 渲染能力 |
| 少量独立装饰 | 复用节点，使用已有动画句柄 | 结束、取消、重播时回收；先测高峰 |
| 密集的纯装饰粒子 | 按前后层共享少量 Canvas，统一帧循环 | 不要一颗粒子一个 Canvas；Canvas 仍由 CPU 栅格化 |
| 旋转矩形、线段、四边形火花 | 新版 Canvas 的 fillQuad，一次提交四个顶点 | 原生扫描线；不是浏览器完整 Path2D，详见脚本合同 |
| 小图标粒子 | 复用离屏图集与 drawImage | 只支持 Canvas 来源，最近邻；旋转图集需说明角度量化差异 |

## 不能这样写

- 密集粒子逐个 createElement、插入/删除节点、修改 class 或启动独立 DOM 动画。树和选择器相关变动可能触发全树重新匹配，不能当成 GPU 精灵批次。
- 在每颗粒子的每帧里解析 transform 字符串、正则拆数值、查询选择器、getComputedStyle 或读布局再写布局。预先保存引用、几何和数值参数，帧内只做必要插值。
- 在 JavaScript 中逐像素或逐扫描线绘制旋转图形。用 fillQuad；图片用共享图集，不能给每颗粒子重建、解包或复制图集。
- 把所有内容塞进全屏 Canvas，或每颗粒子新建 Canvas。文字、实体、物品、复杂遮罩仍走各自支持的原生能力；Canvas 没有自动 GPU 加速承诺。
- 反复写 width/height 来清屏（会重新分配表面），或者活动粒子为零仍保留循环。清屏用 clearRect；关闭、重复触发、重播、离页要取消延迟任务、动画句柄和帧回调。
- 把静止期间的 60 FPS 当动画性能，把离线预览耗时当 Minecraft FPS，或只测一页就声称所有模板已优化。
- 直接放宽沙箱限额来掩盖卡顿，或为了性能删掉退出动画、粒子数量、光效层次。

## 怎么验收

1. **保留基线**：固定库版本、页面文件、随机种子、尺寸、GUI 缩放与动作序列。先录最卡阶段，再改代码；区分首次加载与持续播放。
2. **分清开销**：游戏用 JFR/性能采样确认脚本、样式/布局、CPU 绘制、纹理上传、GC 的占比。离线预览可定位 CPU 热点，不能证明游戏 GPU 和帧率。
3. **一次改一层**：图集采样、扫描线、节点或定时任务分别对照。新版 drawImage 复用行缓冲并预计算横向采样；小范围自拷贝仍保留快照，不改变重叠语义。
4. **重复最重动作**：至少三轮同一段动画，另测连续触发五次、结束、重播、关闭再打开、减少动效。记录中位耗时、长帧/低帧和分配量；基准期间不要并行构建。
5. **检查画面与清理**：640×360、427×240；数量/轨迹和关键阶段截图对照；连续触发后任务、节点与内存不能不断累积。未实测的环境明确标注。
6. **形成回归**：引擎修改先添加能复现问题的用例，再修改实现。像素对照覆盖 alpha、裁剪、缩放、重叠自拷贝、源更新/resize；性能预算测试避免依赖某台机器绝对 FPS。

60 FPS 的整帧预算约 16.7 ms，属于游戏和全部模组共同使用。每页应按目标机器制定自己的预算；不存在一个通用的“安全粒子数量”。已有画布像素上限见 [安全与设置](security.md)，不能用它代替性能测试。

## 列表图片懒加载

长列表的 PNG 使用 `<img loading="lazy" src="cover.png" width="80" height="45">`；CSS 的 URL 背景在该元素添加布尔属性 `data-oriel-lazy`。无需脚本、`data-oriel-shell` 或 `.o-lazy`。缺省或 `loading="eager"` 保持立即读取；`.o-lazy` 仍只负责内容揭开。

- 引擎在布局后判断位置：窗口和各层滚动容器分别向两侧扩展半个视口，取交集；横向滚动也适用。隐藏、脱离文档和远处元素不进入队列。变换按包围盒近似；不检测被其他元素遮挡。
- 每文档默认每 50ms 最多启动 3 个图片源的读取与纹理准备（低帧率时不补发错过的批次）。在 `<html data-oriel-lazy-budget="2">` 设置 1–64 的整数；非法值报 `lazy-image-budget` 警告并采用默认 3。img 和多层 URL 背景共用预算；不同元素重复引用同一 URL 时仍各占一份预算，同元素的重复层合并，宿主缓存可复用资源。
- 必须用 width/height 属性或 CSS 明确预留尺寸；两边尺寸固定时，加载前后布局不变。只给一边或依赖自然尺寸不能保证不跳动。动态插入、改变 src、滚动和筛选后都会重新判断；未启动的元素移除即取消，关闭页面清空队列。
- 本阶段只做加载侧：已加载图片滚远后不主动释放，资源仍按宿主缓存/资源重载生命周期管理。`data-oriel-lazy` 仅作用于元素自身的 URL 背景，不继承、不处理伪元素、mask、border-image、渐变或精灵图集；不增加远程 URL/data URL 支持。
- 预览器用同一引擎队列；PNG 大小检查可以读取远处图片的文件头，这是检查器行为，不是游戏纹理加载。预算是图片个数，不是帧耗时保证，大图仍要缩图。引擎回归覆盖 200 张图的分批请求；游戏滚动空白/闪烁和实际帧率需另行验证。

最小背景图示例：`<div data-oriel-lazy style="width:80px;height:45px;background-image:url(cover.png);background-size:cover"></div>`。同页图片/URL 背景超过 24 处且完全未启用懒加载时，检查器报 `images-without-lazy`。

自定义引擎宿主：`Host.prepareImage(String resolvedUrl)` 在图片获准进入批次后调用，返回 void，默认空实现；若 `imageSize` 只读文件头，应在此准备解码/纹理，并复用绘制时的缓存。Minecraft 宿主已接入文件夹纹理和资源包纹理准备；预览器的 imageSize 本身会解码。不实现此钩子的第三方宿主仍受请求准入限制，但不能保证绘制时的解码工作分摊到这些批次。

## 库升级与交付

页面保存可以热重载，Java 引擎或脚本绑定改变需要更新 jar 或重启开发客户端，不能说保存页面就换了库。使用 fillQuad 前检测 `typeof ctx.fillQuad === "function"`；旧版可以保留已测的扫描线兼容实现，但必须说明旧版不享有这项优化。

发布前对准确的提交内容执行测试、严格 UI 检查、后端边界检查和目标加载器构建。日志、JFR、截图、运行目录、个人模板与原视频素材留在工作区，不加入库提交。只上传源码、必要回归与维护文档，核对 GitHub 仓库、账号和实际远端提交。


## 实验选择器的测量边界

属性规则候选按元素实际属性名查询，避免 hover 重算扫描整张样式表的空属性桶。比较仍须固定输入，按页面/动作分别报告中位数和 p95，并先用同一旧实现的 A/A 对照确定噪声底，不能用合成大页面收益抵消小页面回退。
仅含基础谓词的 compound 使用直接程序，减少逐谓词 lambda 分派；预算计数仍精确覆盖实际求值，不能靠关闭预算换取性能。复杂关系与函数选择器也要单独测量，不以简单属性场景代替。

选择器 `new` 实验模式对简单属性与相对 `:has` 使用保守反向失效，`nth(of)` 在单次匹配中复用兄弟排名。仍遍历树更新继承，复杂关系保留全树匹配；默认 `new`（`old` 回退）。查询诊断耗时不能作为运行时基准，详见 [选择器诊断](selector-debug.md)。

属性解释：预览器新增 `--why-property <property> <element-query>`；MCP `oriel_inspect` 的 selector/property 二选一，page/element 必填，frames 默认 1（1–600）。仅加载无头预览，不批准、不接入或启动游戏。字段、伪元素、实验开关和限制见 [实验层叠与属性解释](d36-r04.md)。
