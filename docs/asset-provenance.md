# 素材来源与许可登记

[文档入口](index.md) · [LICENSE](../LICENSE) · [NOTICE](../NOTICE)

[逐文件清单](asset-provenance.json)登记 Git 跟踪的位图、SVG 和字体文件，包含路径、SHA-256、是否随运行资源打包、来源线索、许可文件及待确认状态。测试截图与模板说明图也单独登记；不把它们当成运行素材。HTML/CSS、字体 provider JSON、运行时画布及从玩家本机 Minecraft 读取的资源不属于这份二进制素材清单。

`license-documented` 仅表示有已记录的来源与许可声明，不是独立法律审查或上游下载认证。`needs-user-confirmation` 表示**需用户确认**，不得根据文件在 MIT 仓库中、脚本生成成功或图片外观推断已经取得授权。`source: null` 表示尚无可靠来源记录。

## 字体与上游素材

字体原项目、版本线索与子集处理见 NOTICE。清单将每个字体关联到实际携带的许可文本：Fusion Pixel 同时保留七份组件声明；Cubic 11 文本包含自身与多个来源字体的条款，不能只看 `-OFL.txt` 文件名。Noto Sans SC 实例化为 weight 400，霞鹜文楷子集改名 Oriel Kai，Smiley Sans 按 NOTICE 保留原文件。来源 URL 仅用于定位，仍应保留下载版本、原始归档及转换脚本的对应关系；可变分支链接不能代替固定归档。

与导入提交逐字节相同的上游图示标记 `upstreamByteMatch: true`，沿用 Vellum MIT 声明。经过修改的文件保留来源线索，但其新增内容的授权须另核对，不把原始 MIT 声明扩大到未追溯的部分。

## 生成图标、主题贴图与其他图片

`workspace:tools/...` 是仓库外工具的来源线索，表示目前还不能从公开源码仓库取得该生成器。`generatorByteMatch` 只表示在隔离目录生成的字节与所登记素材一致，不授予再分发权。图标对应几何生成器（三种粗细），Ore 贴图对应像素绘制脚本；这些脚本没有随本仓库发布的明确授权记录，清单保留“需用户确认”。不要直接重新生成到资源目录。

背景、徽章、模板缩略图以及不能完全对应上游原图的模组图标，也须提供制作来源、原图或生成服务及其适用条款、修改链和发布许可。当前不将未知图片擅自归类为 AI 生成、Mojang 官方或项目原创。

## 核对与维护

```sh
node tools/check-asset-provenance.mjs
node tools/check-asset-provenance.mjs --require-cleared
```

默认命令检查文件集合、素材字节、许可文件字节与基本证据字段；成功**不表示**待确认素材已获许可。`--require-cleared` 额外拒绝随运行资源打包的待确认素材，当前预期失败；该命令尚未接入自动发布流程。两者退出码 0 表示对应检查通过，1 表示有未满足条目，错误会列出具体路径。

新增、替换或删除素材时，同步清单，并审查来源和许可；不要为了消除哈希错误而自动覆盖来源或状态。维护者可在仓库外保存生成器重放结果、原始归档与授权凭据；对外发布所需的许可和源文件则须放入可取得的正式交付物。许可确认后由维护者核对凭据再修改状态，Agent 不代替用户作出授权声明。

Rhino 另按 MPL-2.0 保留固定上游提交、许可证、补丁和 SOURCE 说明。发布者须让接收方能取得**与所发 JAR 对应**的源码及补丁；仅有仓库 URL、相同版本号或本地工作树不证明特定发行字节有可下载的对应源码。生成器、字体原始输入与 Rhino 对应版本的公开可取得性应分别核对。
